# 🔒 活體驗證升級說明

## 📋 新增改進項目

### 1️⃣ **降低 Laplacian 方差閾值** 
- **舊**: 1500 (太寬鬆)
- **新**: 600 (更敏感，能檢測照片)
- **效果**: 靜止照片的紋理特徵會被快速檢出

### 2️⃣ **FFT 頻域 Moiré 檢測**
- 新增 `detectScreenMoireViaFFT()` 函數
- 檢測屏幕典型重複圖案 (60-120Hz)
- **效果**: 翻拍手機屏幕、平板、電腦畫面 → 立即拒絕 ✗

### 3️⃣ **皮膚紋理一致性分析**
- 新增 `analyzeSkinTextureCoherence()` 函數
- 採樣隨機皮膚像素，檢測局部方差
- **效果**: 照片的皮膚紋理通常不自然 → 檢出非活體

### 4️⃣ **強制 4 步驟多層驗證 (不可跳過)**
```
✓ 第 1 步: 遮擋物檢測 (口罩、眼鏡、瀏海)
  ↓
✓ 第 2 步: 眨眼檢測 (眼睛亮度變化) - 必須 ≥12 差異值
  ↓
✓ 第 3 步: 紋理分析 (Laplacian + FFT + 一致性)
  ↓
✓ 第 4 步: 最終挑戰-響應 (眨眼/微笑 - 強制驗證)
```

### 5️⃣ **增強挑戰-響應機制**
**舊版**: 'blink' 或 'turn' (轉頭常失敗)  
**新版**: 'blink' 或 'smile' (更容易感知、更難騙)

- **眨眼挑戰**: 要求 ≥12 亮度變化值
- **微笑挑戰**: 檢測表情方差變化 >50
- **兩者都未通過** → 照片無法通過 ✗

---

## 🎯 為何照片無法通過？

| 檢測項目 | 活人 ✓ | 靜止照片 ✗ |
|--------|--------|----------|
| **遮擋物** | 無遮擋 | 常見 (面部完全靜止) |
| **眨眼** | 會眨眼 | 不眨眼 (亮度差異 <5) |
| **Laplacian** | 自然紋理 | 高於 600 或低於 200 |
| **FFT Moiré** | 無 | 屏幕圖案 >5000 分 |
| **紋理一致性** | >50 分 | <50 分 (不自然) |
| **挑戰-響應** | 可眨眼/微笑 | 無法改變表情 ✗ |

**結論**: 照片必須同時通過所有 6 項檢查才能提取膚色 → **幾乎不可能**

## 🔄 測試流程

### ✅ 測試 1: 真實活人
```
操作: 對著攝像頭，正常眨眼
預期: 所有檢測通過 ✓ → 進入挑戰階段 → 眨眼或微笑後提取膚色
```

### ❌ 測試 2: 手機屏幕照片
```
操作: 拿著手機顯示臉部照片，對著攝像頭
預期流程:
  - Laplacian: 低於 200 或高於 600 → ❌ 失敗 (紋理異常)
  - 或: FFT Moiré: >5000 → ❌ 失敗 (屏幕圖案)
  - 或: 眨眼檢測: 差異 <12 → ❌ 失敗 (無亮度變化)
結果: 拒絕 ✗
```

### ❌ 測試 3: 雜誌/海報照片
```
操作: 拿著印刷的臉部照片，對著攝像頭
預期:
  - Laplacian 或紋理一致性檢測 → ❌ 失敗
結果: 拒絕 ✗
```

### ❌ 測試 4: 視頻重播
```
操作: 在電腦上播放臉部視頻錄製，對著攝像頭
預期:
  - FFT 檢測屏幕幀率特徵 → ❌ 失敗 (5000+ Moiré 分)
  - 或: 紋理不一致 → ❌ 失敗
結果: 拒絕 ✗
```

| 參數 | 舊值 | 新值 | 說明 |

## ⚙️ 調整建議

如果仍然有假陽性/假陰性，可調整以下參數：

```javascript
// 降低難度（允許更多人通過）
if (blinkDiff >= 10)  // 從 12 降到 10
if (expressionChange > 40)  // 從 50 降到 40
if (lapVar > 800)  // 從 600 升到 800

// 提高難度（完全阻止照片）
if (blinkDiff >= 14)  // 從 12 升到 14
if (expressionChange > 60)  // 從 50 升到 60
if (lapVar > 500)  // 從 600 降到 500
```
